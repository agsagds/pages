06Глава II · Снаряжение

Модель: Unsloth + LoRA

полевой код · модельpython
model = FastSentenceTransformer.from_pretrained(
    args.base_model,
    max_seq_length=args.max_seq_length,
    full_finetuning=False,
)
model = FastSentenceTransformer.get_peft_model(
    model,
    r=args.lora_r,
    target_modules=["query", "key", "value", "dense"],
    lora_alpha=args.lora_alpha,
    lora_dropout=args.lora_dropout,
    bias="none",
    use_gradient_checkpointing="unsloth",
    random_state=args.seed,
    use_rslora=False,
    task_type="FEATURE_EXTRACTION",
)
  • Base: unsloth/all-MiniLM-L6-v2, full_finetuning=False — учим только LoRA-патч
  • target_modules — имена Linear-слоёв в графе BERT, из которого сделан MiniLM: проекции внимания query / key / value («на какие слова в предложении смотреть») и dense-слои
  • В Llama/Gemma те же роли зовутся q_proj, k_proj. Gemma-список на MiniLM не найдёт слои, и обучение ничего не сдвинет
  • r=32 — ранг, толщина патча: больше r — больше свободы у A/B и легче запомнить учебные фразы
  • lora_alpha=64 масштабирует поправку как alpha / r, здесь 2. Поднимаешь r — поднимай alpha пропорционально, иначе вместе с ёмкостью меняется сила шага
  • task_type="FEATURE_EXTRACTION": PEFT извлекает вектор признаков
  • dropout=0, bias="none", use_rslora=False — дефолты Unsloth: нулевая регуляризация, замороженные свободные члены, классическая LoRA
  • use_gradient_checkpointing="unsloth" экономит память
  • random_state фиксирует случайность, прогон воспроизводим
07Глава II · Снаряжение

Тренер и лосс MNRL

полевой код · тренерpython
training_args = SentenceTransformerTrainingArguments(
    ...
    per_device_train_batch_size=args.batch_size,
    learning_rate=args.learning_rate,
    warmup_steps=0.1,
    batch_sampler=BatchSamplers.NO_DUPLICATES,
)
trainer = SentenceTransformerTrainer(
    model=model,
    args=training_args,
    train_dataset=train_dataset,
    eval_dataset=eval_dataset,
    loss=MultipleNegativesRankingLoss(model),
)
trainer.train()
  • MNRL: «среди нескольких кандидатов в этом же батче найди своего». 16 пар → модель эмбеддит 16 страниц и 16 описаний; для каждой страницы косинусное сходство со всеми 16 описаниями (от −1 до 1); правильный — свой, остальные 15 — бесплатные negatives из соседей по батчу
  • Размер батча определяет число «чужих» в сравнении: больше батч — больше negatives
  • gradient_accumulation увеличивает шаг оптимизатора, но соседей MNRL не добавляет: сравнение идёт внутри мелкого куска
  • NO_DUPLICATES запрещает дубликаты текстов в батче: у страниц одной категории описание одно; с дубликатами модель учили бы отталкиваться от своего же эталона
  • learning_rate=2e-4 — шаг по A/B, на порядок больше, чем 2e-5 при полном файнтюне MiniLM: патч маленький, двигаем смелее
  • Три эпохи — три полных прохода по таблице
  • warmup_steps=0.1 в текущем transformers — доля шагов: первые 10% lr плавно поднимают с нуля, чтобы случайные A/B сразу не дёрнуть слишком сильно
  • fp16/bf16 — часть операций в меньшем числе бит, быстрее и экономнее по памяти; выбор зависит от видеокарты

Проверка: косинус и argmax

полевой код · проверкаpython
text_emb  = model.encode(texts, convert_to_numpy=True, normalize_embeddings=True)
label_emb = model.encode(label_texts, convert_to_numpy=True, normalize_embeddings=True)
sims      = cos_sim(text_emb, label_emb).cpu().numpy()
pred_idx  = sims.argmax(axis=1)
  • Берём страницы, которых модель не учила, и все описания категорий
  • normalize_embeddings=True сжимает каждый вектор до длины 1: косинус совпадает со скалярным произведением, «громкость» вектора маскируется под «похожесть»
  • Строка матрицы сходств — одна страница против всех описаний; argmax — индекс самого близкого, это и есть ответ модели
  • Тот же вопрос, что задаёт MNRL, только среди полного списка категорий, а не 16 случайных соседей
  • Сравниваем исходную MiniLM и LoRA-версию: ближе к правильному описанию стало чаще — сдвиг сработал

10Глава III · Перевал

Железо: фейковый ROCm и мёртвый GPU

Первые запуски падали с ошибками ROCm.

  • ROCm — открытый стек AMD для вычислений на GPU
  • В ноутбуке NVIDIA RTX 5060, Torch на CUDA 13
  • Unsloth увидел /dev/kfd от встроенной AMD-графики (iGPU) и полез в AMD-путь
  • NVIDIA GPU была мертва для CUDA — torch.cuda.is_available() == False, remapped_rows кричит «GPU requires reset»
  • Тихий фолбэк на vanilla ST скрыл проблему
  • Фикс: CUDA preflight перед train, пиннуем Torch на CUDA-индекс, ребут машины
  • После ребута: cuda_ok, LoRA-чекпоинтинг живой, ~54 samples/s
  • Варны про Python.h, Triton и position_ids — шум
11Глава III · Перевал

Trouble 2: метрики не двинулись

Первый «настоящий» eval после Unsloth показал дельту около нуля.

  • accuracy@1: 1.00 → 1.00
  • косинус к верному лейблу: ~0.97 уже на base
  • дельта: +0.002
12Глава III · Перевал

Root cause: saturated eval + немердженые адаптеры

Две проблемы сразу.

  • Eval сатурнирован: синтетика была копией промпта таксономии. Base на таком не может ошибиться.
  • В «merged»-чекпоинте остались файлы LoRA-адаптеров.

Обычный SentenceTransformer адаптеры просто игнорирует — tuned ведёт себя как base.

13Глава III · Перевал

Фикс: честный merge + жёсткий eval

Merge делаем проверяемым, eval — нечитерским.

  • save_pretrained_merged(..., save_method="merged_16bit")
  • адаптеры остались — merge_and_unload
  • adapter_config.json после merge — фейлим ран
  • merged_has_adapters=False — критерий успеха
  • вместо копий промптов — сниппеты, похожие на страницы

19Глава IV · Новые земли

Решение по длинным страницам

MiniLM живёт в окне 256 токенов.

  • encode() трункейтит
  • оставляем трункацию
  • без chunk-mean-pooling
  • без chunk-voting

Правило: считаются только первые 256 токенов.

20Глава IV · Новые земли

Контракт разметки

Человек размечает окно, которое видит модель.

  • text кандидата = encode/decode токенизатором на 256 токенов
  • полный body страницы в лист не кладём
  • was_truncated = yes/no
  • судим только по text
  • окно не категоризуется — скипаем строку

27Глава V · Вторая вершина

Что значат метрики

Считаются дважды на одном eval-сете: base и tuned.

Предсказание — cosine argmax по всем промптам таксономии.

метрикасмыслкак читать
accuracy@1Доля страниц, где ближайший промпт — верный лейблОсновная метрика. 0.31 — это 14 из 45.
accuracy@3Верный лейбл в тройке ближайших промптовНужна, когда соседние IAB близки.
macro-F1F1 по каждому верному классу, затем среднееНе завышается частыми классами. На Phase 2 почти все eval-классы — по одному примеру, поэтому macro-F1 ≈ accuracy@1.
mean sim to goldСредний косинус страницы к верному описаниюРост значит: страница ближе к верному промпту, даже если top-1 ещё другой.
mean_marginsim(pred) − sim(gold)Ниже — лучше. Если top-1 верен, margin = 0. Если нет — насколько победил неверный промпт. Минус в delta — улучшение.
